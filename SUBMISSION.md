# Building the official submission zip

The competition requires a `<team_name>_submission.zip` with this exact structure (from the
organizers' submission page):

```
<team_name>_submission.zip
├── output/
│   ├── matching_results.tsv     # final matches, same file uploaded to the leaderboard
│   └── candidate_pairs.tsv      # blocking candidate set
├── code/
│   └── business_entity_resolution/
│       ├── src/                 # all source code
│       ├── README.md            # end-to-end reproduction instructions
│       └── requirements.txt     # pinned dependencies / environment
└── Documentation_template.md    # completed methodology write-up
```

This repo was reorganized for GitHub after the competition closed (flat `src/`, `results/`,
`docs/`), so that exact layout doesn't exist on disk anymore. Everything needed to rebuild it
is still here except one file.

**Shortcut:** [`tools/build_submission.ps1`](tools/build_submission.ps1) does all four steps
below in one go (it reads `candidate_pairs.tsv` from `output9\` by default) and writes the zip
to `submission\`:

```powershell
.\tools\build_submission.ps1 -TeamName "YourTeam" -Members "Name One, Name Two"
```

The manual steps:

## 1. Get `candidate_pairs.tsv`

Not tracked in this repo — it runs 2.5GB+ per variant and was deliberately gitignored. The
`resolve` stage writes it in the same output directory as `matching_results.tsv`
(`src/v3/resolve.py`), so on whichever machine the final run actually happened on, it should
be sitting right next to the `matching_results.tsv` that became
[`results/final_submission/matching_results.tsv`](results/final_submission/matching_results.tsv)
— the `output9/` folder from `tools/run_v3_refine.ps1 -Out output9` (`..\..\output9` under
the old pre-reorg layout). Copy it in:

```bash
cp /path/to/output9/candidate_pairs.tsv results/final_submission/candidate_pairs.tsv
```

If that file genuinely no longer exists anywhere, it has to be regenerated by rerunning the
`resolve` stage against the same `work3/` intermediate state — see
[`docs/runbook.md`](docs/runbook.md).

## 2. Fill in `Documentation_template.md`

[`docs/methodology.md`](docs/methodology.md) is the completed write-up, but it still carries
the unfilled placeholders from the original template (`[Your Team Name]`,
`[List all team members]`). Copy it out under the exact filename the rules ask for, then
fill those two lines in:

```bash
cp docs/methodology.md Documentation_template.md
# edit Documentation_template.md: replace [Your Team Name] and [List all team members]
```

(The rules say there's no need to rename the file, and a PDF export is also acceptable if
you'd rather submit that instead of the `.md`.)

## 3. Assemble the zip

```bash
rm -rf _submission && mkdir -p _submission/output _submission/code/business_entity_resolution

cp results/final_submission/matching_results.tsv _submission/output/
cp results/final_submission/candidate_pairs.tsv  _submission/output/          # after step 1
cp -r src                    _submission/code/business_entity_resolution/src
cp requirements-lock.txt     _submission/code/business_entity_resolution/requirements.txt
cp docs/runbook.md           _submission/code/business_entity_resolution/README.md
cp Documentation_template.md _submission/                                    # after step 2

cd _submission && zip -r "../<team_name>_submission.zip" . && cd ..
rm -rf _submission
```

Replace `<team_name>` with your actual team name before zipping.

## 4. Validate before uploading

```bash
python3 tools/validate_submission.py \
    --matching  results/final_submission/matching_results.tsv \
    --candidate results/final_submission/candidate_pairs.tsv \
    --test-dir  student_resource/dataset/test
```

`PASS` means it's safe to upload. `matching_results.tsv` is the one that was already scored
on the leaderboard (0.985018, rank #568) — this just confirms the zip's copy matches
byte-for-byte and the pair `candidate_pairs.tsv` is well-formed.

## Once the zip is submitted

This file (`SUBMISSION.md`) and the `_submission/` staging folder it describes are scratch —
safe to delete from the repo afterward if you don't want them showing up in the public
GitHub history. `results/final_submission/candidate_pairs.tsv` should stay gitignored either
way (`*.tsv` is ignored by default; only the three `results/*/matching_results.tsv` files
have an explicit exception in `.gitignore`).
